# 산책로 추천 설계

"이 길이 강아지 산책로로 괜찮은가"를 어떻게 판단할지에 대한 설계 문서.
구현은 GPS 기록/이력(v1)이 안정된 뒤에 시작한다.

## 왜 코스가 아니라 세그먼트인가

산책로 DB를 통째로 구해서 추천하려고 하면 데이터가 없어서 막힌다.
대신 길을 100m 단위 **세그먼트**로 쪼개고 세그먼트마다 점수를 매긴 뒤,
코스는 세그먼트를 이어붙여 생성한다.

이렇게 하면 산책로로 등록된 길이 아니어도, 사용자가 어디에 있든
"지금 여기서 30분 순환 코스"를 만들어낼 수 있다.

세그먼트 점수를 pgRouting의 cost로 넣으면

```
cost = 거리 ÷ 적합도점수
```

"최단 경로"가 아니라 **"가장 산책하기 좋은 경로"** 가 나온다.
이게 이 앱의 엔진이다.

## 하드 필터 (점수 계산 이전에 배제)

- 반려동물 출입금지 구역 — 일부 어린이공원, 특정 하천 둔치, 생태보호구역
- 여름철 지면온도 위험 시간대 — 기온 30℃ 이상 + 아스팔트 구간이면 12~16시 제외
- 보도가 없는 차도, 자전거 전용도로

## 가중 점수

각 지표를 0~1로 정규화한 뒤 가중합해서 0~100으로 만든다.

| 지표 | 가중치 | 판단 근거 |
|---|---|---|
| 노면 재질 | 20% | 흙·마사토·우레탄 1.0 / 잔디 0.9 / 보도블럭 0.6 / 아스팔트 0.3 — 발바닥 화상과 관절 부담 |
| 차도 분리도 | 20% | 차도까지 평균 이격거리, km당 무신호 횡단 횟수 |
| 그늘·녹지 | 15% | 가로수 캐노피 비율, 공원 폴리곤 내부 통과 비율 |
| 편의시설 | 15% | 배변봉투함·음수대·벤치, 반경 1km 내 동물병원 |
| 경사도 | 10% | 누적상승고도 ÷ 거리 — 노령견과 단두종에 특히 중요 |
| 혼잡·소음 | 10% | 시간대별 유동인구, 간선도로 근접 소음 |
| 순환성 | 10% | 출발점 = 도착점 루프인지, 접근 거리 |

## 데이터 소스 (국내 기준)

- **OSM** — 세그먼트 그래프의 뼈대. `highway=footway/path`, `surface`,
  `natural=tree_row` 태그가 노면과 그늘 정보를 그대로 준다. 무료고 가장 중요.
- **공공데이터포털** — 전국도시공원표준데이터, 지자체 반려동물 놀이터,
  동물병원 인허가 정보
- **한국관광공사 TourAPI** — 반려동물 동반 가능 시설
- **기상청 단기예보 + 에어코리아** — 실시간 하드 필터 (폭염, 미세먼지)
- **수치표고모델(DEM)** — 경사도
- **유저 GPS 트랙 (크라우드소싱)** — 서비스가 돌기 시작하면 이게 최고의
  데이터가 된다. 실제로 개를 데리고 많이 걷는 길 = 좋은 길.

각 API의 정확한 엔드포인트와 신청 절차는 실제로 붙일 때 확인이 필요하다.

## 개인화

### 콜드스타트 — 온보딩 입력만으로 가중치를 바꾼다

학습 데이터가 없는 초기에는 이것만으로 충분하다.

- 견종·체중·나이 → 목표 거리/시간, 경사 가중치
- 성향(사교적 / 예민 / 다른 개를 무서워함) → 혼잡도 가중치
  (예민한 아이는 혼잡도 가중치를 30%로 올린다)
- 단두종 체크 → 여름 하드 필터 강화

### 이력 기반 — GPS 트랙 자체가 만족도 신호다

별점을 따로 받지 않아도 기록에서 신호를 뽑을 수 있다.

- **재방문 횟수** — 가장 강한 신호. 좋았으니 또 갔다.
- **완주율** — 중간에 끊었으면 별로였다는 뜻
- **정지 시간 비율** — 강아지가 냄새 맡느라 자주 멈춘 구간 = 좋아하는 구간.
  v1의 `Walk.sniffRatio` 가 이 값이다.
- **평균 속도가 유난히 빠른 구간** — 빨리 벗어나고 싶었던 구간

이 값들을 세그먼트 점수에 개인 보정치로 더한다.

### 다양성 확보

개인화만 하면 늘 같은 길만 추천된다. ε-greedy로 일정 비율은
아직 안 가본 코스를 섞는다.

## 구현 순서

1. **v1 — 기록 (현재)**
   GPS 기록, 노이즈 제거, 이력, 코스 자동 묶기. 추천 없음.

2. **v2 — 규칙 기반 추천**
   OSM + 공공데이터로 세그먼트 점수화 → pgRouting으로 코스 생성.
   개인화 없이도 서비스가 된다.

3. **v3 — 개인화**
   이력 기반 세그먼트 보정 + ε-greedy.

## 백엔드

- Spring Boot + PostgreSQL/PostGIS + pgRouting
- 공간 쿼리와 경로 생성이 전부 DB 레벨에서 해결된다
- 주의: 현재 개발 PC의 JDK는 1.7이라(레거시 프로젝트용) Spring Boot 3에
  쓸 JDK 17 이상을 따로 설치해야 한다
