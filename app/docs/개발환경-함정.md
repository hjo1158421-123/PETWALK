## 빌드 / 실행

### `flutter run` 이 떠 있으면 `flutter test` 가 멈춘다

Flutter 가 프로젝트 락을 잡는다. 아무 출력도 없이 몇 분씩 대기한다.
**테스트 전에 dev 서버를 먼저 내릴 것.**

### 갑자기 `package:sqflite/sqflite.dart` 를 못 찾는다고 할 때

에디터에 `Undefined name 'databaseFactory'`, `Target of URI doesn't exist`
같은 에러가 수십 개씩 뜬다. import 는 멀쩡한데 전부 undefined 다.

`.dart_tool/package_config.json` 이 pub cache 의 **없는 버전**을 가리키고
있어서다. 파일에는 `sqflite-2.4.3` 이 적혀 있는데 캐시에는 `sqflite-2.4.4`
만 남아 있는 식이다. 캐시가 갱신되면서 낡은 해석 정보만 남으면 이렇게 된다.

→ `flutter pub get` 한 번이면 끝난다.

에디터를 "잘못 열어서" 생긴 문제로 오해하기 쉽다. **`flutter analyze` 로
먼저 확인할 것.** 거기서도 같은 에러가 나오면 에디터가 아니라 패키지
해석 문제다. 반대로 analyze 는 깨끗한데 에디터만 빨갛다면 그건 분석
서버가 낡은 상태를 쥐고 있는 것이니 `Ctrl+Shift+P` →
`Dart: Restart Analysis Server`.

### Gradle 이 JDK 1.6 을 집어 들어 빌드가 즉시 죽는다

```text
UnsupportedClassVersionError: org/gradle/launcher/GradleMain
  : Unsupported major.minor version 52.0
```

52.0 은 Java 8 클래스 파일이다. JDK 1.6 은 50.0 까지만 읽는다. 즉
**Gradle 이 시스템 `JAVA_HOME`(레거시 JDK 1.6)으로 돌고 있다는 뜻**이다.

`JAVA_HOME` 을 고치면 안 된다. 그 JDK 로 레거시 프로젝트가 실제 돌아간다.
진짜 원인은 Flutter 쪽 설정이 풀린 것이다.

```powershell
flutter config --jdk-dir='C:\jdk17'
flutter config --list   # jdk-dir 확인
```

**Git Bash 에서 하지 말 것.** 백슬래시가 먹혀 `C:jdk17` 로 저장된다.
저장은 조용히 성공하고 다음 빌드에서 같은 에러가 다시 난다.
PowerShell 에서 작은따옴표로 줄 것.

이 설정은 폴더를 옮기거나 Flutter 를 갱신하면 풀릴 수 있다. 예전에 한 번
잡아 뒀다고 방심하지 말고 `--list` 로 확인할 것.

### Gradle 빌드가 NDK 를 받다가 멈출 수 있다

첫 릴리스 빌드에서 Gradle 이 NDK(r28c, 약 2.5GB)를 자동으로 내려받는데,
22분간 CPU 0 으로 정지한 적이 있다. 프로세스를 정리하고 다시 돌리니
NDK 가 캐시된 상태라 99초 만에 끝났다.

멈춘 것 같으면 Gradle 데몬의 CPU 누적치를 확인한다. 늘지 않으면 정지다.

```powershell
Get-Process java | Select-Object Id,CPU,WorkingSet
```

**죽일 때 주의:** 이 PC 에는 레거시 프로젝트가 쓰는 JDK 1.6 자바
프로세스와 IntelliJ 가 같이 떠 있다. 명령줄을 확인해서 `C:\jdk17` 로
시작하는 것만 죽일 것.

## 문자 인코딩 (한국어 때문에 자주 터짐)

### PowerShell 5.1 은 BOM 없는 UTF-8 `.ps1` 을 못 읽는다

ANSI(CP949)로 읽어서 한글이 깨지고 **파싱 자체가 실패한다.**
Git Bash 의 heredoc 으로 쓴 스크립트가 여기 해당한다.

→ **PowerShell 스크립트 안의 메시지는 ASCII 로 쓸 것.**

### perl 은 `use utf8` 없이 한글을 바이트로 취급한다

치환 문자열에 한글이 있으면 이중 인코딩돼서 `ì¹ììë` 같은 게 나온다.

→ 스크립트 파일 맨 위에 `use utf8;` 을 넣고, 읽기/쓰기에
`:encoding(UTF-8)` 을 지정할 것.

### `sed` 는 치환 문자열의 백슬래시를 먹는다

`C:\Android\tmp` 가 `C:Android<TAB>mp` 가 된다.

→ 경로는 슬래시(`C:/Android/tmp`)로 쓰거나 `awk` 로 줄을 바꿀 것.

### perl 치환에서 `$변수명`이 Perl 변수로 해석된다

Dart 코드의 `$cltStage` 같은 걸 치환 문자열에 넣으면 빈 값이 된다.

→ 셸을 거치지 않도록 **스크립트 파일에 써서 실행**할 것. 셸 한 줄
치환은 이스케이프가 겹쳐서 거의 항상 깨진다.

## 파일 조작

### `Move-Item` / `Directory.Move` 가 "Access denied" 로 실패한다

갓 압축 해제한 디렉터리를 옮기려 하면 Defender 가 스캔하면서 잠근다.

→ `robocopy <src> <dst> /E` 로 복사하고 원본을 지울 것. 잠금에 강하다.

### MAX_PATH 260자 제한

스크래치패드 경로가 이미 길어서, 그 아래에 긴 이름의 파일(예: Android
cmdline-tools 안의 guava jar)을 풀면 넘친다.

→ 압축 해제는 `C:\Android\tmp` 같은 **짧은 경로**에서 할 것.

### Bash 도구의 명령 길이 제한 (약 8KB)

긴 heredoc 이 잘리면서 "unexpected EOF while looking for matching" 로
실패한다. 잘린 위치가 한글 문자열 안이면 원인이 더 헷갈린다.

→ 긴 파일은 `cat >` 와 `cat >>` 로 나눠 쓸 것.

## Android SDK

### sdkmanager 라이선스 수락은 stdin 리다이렉트로

PowerShell 파이프(`$yes | & sdkmanager --licenses`)로는 Java 프로세스
stdin 까지 도달하지 않는다. 수락됐다고 출력되지만 실제로는 안 된다.
그 뒤 패키지 설치가 "license is not accepted" 로 조용히 건너뛰어진다.

→ 파일 리다이렉트를 쓸 것.

```bash
yes y | head -200 > /c/Android/yes.txt
/c/Android/Sdk/cmdline-tools/latest/bin/sdkmanager.bat --sdk_root='C:\Android\Sdk' --licenses < /c/Android/yes.txt
```

수락이 실제로 됐는지는 `C:\Android\Sdk\licenses\` 에 파일이 생겼는지로
확인한다.

## 웹 (Chrome) 확인

### `flutter run -d chrome` 이 이 PC 에서는 절대 안 된다 (회사 보안 정책)

```text
Failed to launch browser after 3 tries.
```

Chrome 이나 Flutter 문제가 아니다. **회사에서 내려보낸 Chrome 정책과
Flutter 가 붙이는 실행 플래그가 충돌한다.**

`HKLM\SOFTWARE\Policies\Google\Chrome` 에 DLP 성격의 정책이 걸려 있다.

| 정책 | 내용 |
| --- | --- |
| `ExtensionInstallForcelist` | 확장 강제 설치 (`aeeleemfafepeofgolmcmcpbocaeedmk`) |
| `DisableScreenshots` | 스크린샷 차단 |
| `IncognitoModeAvailability` | 시크릿 모드 제한 |
| `BrowserGuestModeEnabled` | 게스트 모드 제어 |

Flutter 는 Chrome 을 띄울 때 `--disable-extensions` 를 **항상** 붙인다.
정책은 "이 확장은 반드시 켜져 있어야 한다"고 강제하므로 둘이 부딪혀
Chrome 이 기동 자체를 못 하고, Flutter 는 디버깅 포트 응답을 못 받아
3번 재시도 후 포기한다.

플래그를 하나씩 분리해 확인한 결과다. `--disable-extensions` **단독으로
실패**하고, 나머지(`--bwsi`, `--disable-popup-blocking`,
`--disable-background-timer-throttling`, `--disable-translate` 등)는 전부
정상이었다. Edge 에도 같은 forcelist 가 걸려 있어 `-d edge` 도 기대하기
어렵다.

**정책은 건드리지 말 것.** 관리자 권한이 필요하고 회사 보안 정책을
우회하는 행위다. 대신 아래 web-server 를 쓴다.

### 그래서 웹 확인은 `-d web-server` 로 한다

Flutter 가 브라우저를 직접 띄우지 않고 URL 만 연다. 정책과 부딪힐 일이
없다. 평소 쓰는 Chrome 으로 `http://localhost:8080` 을 직접 열면 된다.

```bash
cd /c/PETWALK/app && export PATH="/c/flutter/bin:$PATH" && flutter run -d web-server --web-port=8080 --web-hostname=localhost
```

VS Code 에서는 F5 → **`PETWALK (web-server :8080)`** 구성으로 같은 게
뜬다. 중단점은 Chrome DevTools(`F12`) → Sources 에서 `.dart` 파일에 직접
건다. 소스맵이 실려 있다.

브라우저로 페이지를 열기 전까지는
`Waiting for connection from debug service on Web Server...` 에서 멈춰
있는 게 정상이다. 고장이 아니다.

### 포트 8080 이 이미 쓰인다면 지난 세션의 dev 서버다

```text
SocketException: Failed to create server socket (errno = 10048)
```

`flutter run` 을 내리지 않고 세션이 끝나면 `dartvm.exe` 가 살아남아 계속
포트를 물고 있다. 게다가 프로젝트 락도 쥐고 있어서 `flutter test` 까지
막는다. 옛 코드를 서빙하므로 "고쳤는데 화면이 그대로"로도 나타난다.

점유 프로세스를 확인하고, 명령줄이 `flutter run` 인 게 맞으면 정리한다.

```powershell
$c = Get-NetTCPConnection -LocalPort 8080 -State Listen
Get-CimInstance Win32_Process -Filter "ProcessId = $($c.OwningProcess)" | Select-Object CommandLine
```

### 가짜 GPS 를 너무 빠르게 만들면 거리가 0 에서 안 움직인다

실제로 걷지 않고 기록을 확인하려고 가짜 GPS 를 만들었는데, 시간을 아끼려고
6m/0.5초(**12 m/s**)로 걷게 했다. 화면에는 시간만 흐르고 **거리가 계속
0** 이었다.

`GpsFilter.maxSpeedMps` 가 5.5 다. 사람이 낼 수 없는 속도로 튄 좌표는
통째로 버려진다. 필터가 제 일을 한 것이다.

→ **필터 임계값을 시뮬레이터 편의로 바꾸지 말 것.** 실기기 로그로 보정해야
하는 값이다. 대신 시뮬레이터를 4m/1초(4 m/s)로 낮췄다. 그래도 사람이 뛰는
속도라 600m(코스로 묶이는 최소 길이)를 2~3분이면 채운다.

`test/simulated_location_test.dart` 에 이 속도가 필터를 통과하는지 확인하는
테스트를 넣어 뒀다. 빠르게 만들고 싶은 유혹이 또 올 자리다.

### dev 서버는 브라우저 새로고침으로 재컴파일하지 않는다

코드를 고치고 새로고침해도 옛날 JS 가 그대로 뜬다. 핫 리로드 키를
백그라운드 프로세스에 보낼 수 없으므로 **서버를 재시작**해야 한다.
첫 컴파일에 25~30초 걸린다.

### 탭 제목으로 컴파일 완료를 판단할 수 있다

컴파일 전에는 `petwalk`(index.html 의 값), 앱이 뜨면 `PETWALK`
(MaterialApp 의 title)로 바뀐다.

`resize_window` 후에는 페이지를 새로고침해야 제대로 다시 그린다.

## 테스트

### 위젯 테스트 안에서 DB 를 기다리면 끝나지 않는다

`testWidgets` 는 가짜 시계 위에서 돈다. sqflite 는 실제 비동기 I/O 라
완료가 오지 않는다. 8분 타임아웃으로 나타난다.

→ DB 가 얽힌 검증은 `test/` 의 평범한 `test()` 로, 화면 검증은
`integration_test/` 로 나눌 것. 자세한 건
[의사결정-기록.md](의사결정-기록.md) 참조.

### `pumpAndSettle` 이 지도 때문에 타임아웃된다

`flutter_map` 이 타일을 계속 요청해서 프레임이 멈추지 않는다.
`RouteMap.tilesEnabled = false` 로 끄거나, 명시적인 `pump` 를 반복할 것.

### 가짜 좌표를 몇 개만 흘리면 산책이 저장 안 된다

`WalkRecorder` 테스트에서 좌표를 4~5개만 `emit` 했더니 `stop()` 이 계속
`null` 을 돌려줬다. 이동 거리가 `minDistanceM`(30m) 을 못 채운 줄 알았는데
실제 원인은 `GpsFilter.warmupSkip`(3) 이었다.

- 처음 3개 픽스는 무조건 버려진다(측위 안정화 대기)
- 그다음 유효 픽스 1개는 거리 계산의 기준점(anchor)으로만 쓰이고
  `deltaM = 0` 이다
- **거리는 그 이후 픽스부터 쌓인다**

즉 좌표 N개를 흘리면 실제로 거리에 반영되는 건 `N - 4` 개뿐이다. 10m씩
움직이는 좌표를 쓴다면 최소 30m(`minDistanceM`) 를 채우려고 `N - 4 >= 3`,
즉 최소 7개는 흘려야 한다. 넉넉히 10개 이상 쓸 것.
